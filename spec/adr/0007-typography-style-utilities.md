# Named typography style utilities (`text-{size}-{weight}`)

**Status**: accepted

## Context

Figma models typography in espresso v2 as **named styles**, not as independent
size/weight/tracking axes. Each named style is atomic, and text of the same size
is tracked differently per weight — a deliberate optical correction. For example,
`text/base/regular` is 14px with 2% letter-spacing, while `text/base/medium` is
14px with 1.5%.

Tailwind's `fontSize` utility carries `letterSpacing` keyed only by size, and CSS
letter-spacing cannot follow `font-weight`. So `text-base` emits one
letter-spacing whether or not `font-medium` is also applied. Any component
written as `text-base font-medium` drifted from the named style it was meant to
match — visually subtle but systemic.

## Decision

Expose Figma's named typography styles as Tailwind **component utilities**
generated by the design-system plugin, one class per (size, weight):

```css
.text-base-medium { font-size: 14px; line-height: 1.35; font-weight: 500; letter-spacing: 0.015em; }
.text-lg-semibold { font-size: 16px; line-height: 1.35; font-weight: 600; letter-spacing: 0.015em; }
.text-p-base-medium { font-size: 14px; line-height: 1.5; font-weight: 500; letter-spacing: 0.015em; }
```

Regular is the bare `text-{size}` (and `text-p-{size}`) utility, which already
carries the regular weight and the regular tracking. `text-{size}-regular` would
be a redundant alias, so it does not exist.

Components opt in by replacing `text-{size} font-{weight}` with
`text-{size}-{weight}`.

Naming follows Figma's slash convention flattened to hyphens: `text/base/medium`
→ `text-base-medium`, `paragraph/base/medium` → `text-p-base-medium`.

## Rationale

Three alternatives were considered:

1. **Per-component override** (`tracking-[0.015em]` inline in Button).
   Surgical but does not scale — every component re-discovers the rule. Drift
   returns the moment a new component is added.

2. **Auto-tighten on `font-medium` globally**, through a rule that combines
   weight and tracking. Zero migration cost, but it applies to body paragraphs
   too, and paragraph styles carry their own tracking per weight. One global rule
   cannot express two families.

3. **Named-style utilities** (chosen). One class per Figma style, so the CSS and
   the design file use the same vocabulary, and a class is correct on its own
   rather than correct only next to the right `font-*` class.

## Consequences

- The values are generated, not hand-written. `tailwind/tokens/build.js`
  reads the Figma text-styles export into `tailwind/tokens/typography.js`,
  and `buildTextStyleUtilities()` in `tailwind/plugin.js` emits one class per
  (size, weight) from `tracking.text` and `tracking.paragraph`. Adding a style is
  a token re-export, not a code edit.
- A weight class must not be combined with a `font-*` utility. `font-medium`
  after `text-base-medium` changes the weight and leaves the tracking of the
  medium style, which is the drift this ADR removes.
- Migration is mechanical. The `tokens-v2` codemod
  (`tailwind/migrate-tokens-v2.js`) merges a co-located `text-{size}` and
  `font-{weight}` in a static class list into `text-{size}-{weight}`, and drops
  `font-normal` because the bare utility is already regular. Components that
  still spell it the old way render, with the tracking of the regular style.
- `black` emits no class. It was removed in #998 with zero usage, and the Figma
  weight behind it was corrupt export data.

**Historical.** The first version of this ADR shipped three hand-encoded classes
— `text-base-medium`, `text-md-medium` and `text-lg-medium` — from
`FONT_SIZE_MEDIUM_TRACKING` in `tailwind/plugin.js`, because the composite styles
were not in the token export at the time. `b8c232a6dc` replaced that map, and the
regular-weight `FONT_SIZE_AUGMENT` map beside it, with the generated values. The
decision above is unchanged; only its source is.
